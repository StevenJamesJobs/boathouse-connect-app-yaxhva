Threads are realThe server already groups by thread_id and get_message_thread returns the whole conversation, so the inline composer is a client change: send with p_reply_to_message_id = the root and recipients = everyone in the thread but you. Reply / Reply-all buttons go; the one-to-one path is the participants sheet or the mini profile card.
Avatars on cardsThe list already hydrates senders through the org directory, so the single avatar is free; the stack needs the thread’s participant ids on the inbox row — one column in get_inbox. Three faces plus “+N” is the cap.
Swipe actionsKeep two: Read and Delete. Mute has no server concept and “archive” would be a third state we don’t have. Long-press keeps multi-select; the hint line above the list is the only teaching we add.
AttachmentsOne Attach entry, both kinds allowed together (today: one photo, one file, files O/M-only — the limits stay 5 / 10 MB). Both compose directions share the recipients sheet and the three untranslated attach strings get real keys.
Subscription copyThe page is the last one with hardcoded English — every string moves to the subscription namespace in the build. Yearly products are UI-ready only; RevenueCat products come when you say.
Header rhythmAll three messaging pages sit at paddingTop 60 today; ScreenHeader’s 48 lifts them 12pt like every other conversion.
