How the photos are stored · pick one
A · a photo list on the rowRecommended
Each item and recipe row gains an images list (the photo links in display order). The first one stays mirrored into today's thumbnail_url, so every tile, shelf, hub peek and menu card keeps working untouched. The Poster reads the list. One column per table, no joins.
B · one row per photo in a separate table
A content_images table (which item, which photo, what position). Cleaner on paper, but every screen that shows a photo needs a second lookup, and all ten recipe/item write RPCs grow extra round trips.
Both keep the 4-photo cap on the client and the server. A lets the five recipe families + menu items ship in one pass.
